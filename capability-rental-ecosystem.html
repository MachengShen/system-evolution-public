SPEC §0 · 总判词（Source of Truth）

能力租借生态在模型内可以成立，但只对一类能力成立：其价值不在输出 transcript 里，而在 (i) 持续漂移的私有状态、(ii) rival 的物理履约权、(iii) 资本背书的赔付责任、(iv) 不公开且随租借增长的反例库； 并且可触达的转售面 N 被身份绑定 / rival 输出限制住。 静态函数型能力（prompt/GPT 套壳、风格模型、公开数据 RAG）的死因是蒸馏成本 K 一次付清、可被无限下游摊销。 模型预测：平台若不做「已验证结果计量 + 身份绑定担保 + 质押/金丝雀/罚没（含解绑期）+ 裁定与 carry 分权」，会出现柠檬化。 （充分性在模型内论证；必要性未证。）

#arch 反例 4 · 三层架构、数据闭环与冷启动飞轮

L1 Tabelog·Eye (Class A) → L2 StarShard C-Gate (Class D) → L3 SGDAO (Class B+C) · 裁定权与 Carry 分权

阶段 1 · 单人工具期L1 自用

自有场景为唯一用户，只开 L1；验证履约回执计量，实测状态漂移率 λ；组织红队实测蒸馏成本 K。

边界（Opus N9）：只有 1 个用户，此阶段测不出 κ / f / D。

阶段 2 · 核验即服务期L2 C-Gate

L2 C-Gate 作为审计方卖证书给外部供给者；白名单 + 质押；植入已知作弊者实测检出功效 D。

冷启动解法：买方初期不认证书 ⇒ 先在自有 L1/L3 采购中强制要求证书。

阶段 3 · 承保租借市场期L3 SGDAO

开放 L3 担保池与物理履约，启用 take-rate τ + carry χ（裁定权与 carry 严格分权），开放完整 stake / canary / slash 市场。

偿付约束：B ≥ ES_97.5%（当期赔付）+ 共模压力情景。

5 条硬性停机条件（Kill-Conditions） Fail-Closed
  • Kill 1（抗蒸馏证伪）：实测蒸馏判据成立（L1 状态可被下游摊销蒸馏 (rK+λK_inc)/N + L < P）⇒ L1 降级为纯获客工具。
  • Kill 2（核验摩擦过高）：实测 κ / κ_m 使 p − c_H < min F(ν) ⇒ 不开外部市场，只做自营。
  • Kill 3（A 类实地核验过贵）：实测 κ_A 使 A 类能力不可行 ⇒ A 类不入租借市场。
  • Kill 4（金丝雀可被识别）：阶段 2 植入已知作弊者测得 D ≪ 模型预测 ⇒ 退回阶段 2 重构金丝雀不可区分性。
  • Kill 5（担保池穿仓风险）：综合成本率 (赔付+费用)/保费 持续 > 阈值（参数示例 0.8）或 B < ES_97.5% ⇒ 立即停止新承保。
平台单位经济模型（Unit Economics）与分权约束 Take-rate + Carry
平台每期净毛利公式（SPEC §4）
NetMargin/期 = GMV·τ + carry + 证书收入 − κ·抽检量 − κ_m·计费量 − compute
平台收入与核验融资约束（SPEC §3）
Revenue = τ·GMV + χ·max(0, 保费 − 赔付 − 准备金) ，且 τ·p ≥ κ·ν + κ_m
战略铁律：优先走「免费高频工具 (L1) → 高毛利履约/承保 (L3)」，不做低频 C 端前置付费 SaaS。
Carry 四条分权铁律（Opus B6）： (a) 理赔与罚没由独立核验方（或多方 C-Gate 多数决）裁定； (b) 罚没款赔付受害租户或销毁，绝不进 carry 计算基； (c) 设高水位线 + 多期 clawback； (d) 平台私人最优 ν < ν*，必须将 ν 下限写入协议规则。

#audit Claude Opus 独立对抗审计轨迹（B1–B7 阻断项修复与已知边界）

审计结论：PASS-WITH-FIXES · 详见 AUDIT-OPUS.md、AUDIT-OPUS-R2.md 与 SPEC.md
7 个 Blocking 缺陷：问题 → v0.2 修复（R1–R12 已吸收） 7 / 7 Fixed
  • B1（蒸馏判据漏贴现与 N 摊销）：原判据 λK < P 忽略下游转售摊销与贴现 → v0.2 修复：改为 [r·K(ε) + λ·K_inc(ε)] / N + L(ε) < P，指明静态能力死因是 K 一次付清被 N→∞ 摊销，且 A 类同样需防爬虫轮询摊销。
  • B2（罚没 IC 近似方向标反）：原将 Δc/(νf) 当作近似值（实为 Bernoulli 下界，系统性低估质押） → v0.2 修复：定质押强制用精确式 S* = nΔc / (δ^L · D)，明确标注 Δc/(νf) 为下界，并说明大 n 区域摩擦有下限 ≈ ρΔc。
  • B3（漏算诚实方误罚税与反向柠檬化）：原 F* 忽略 f_H > 0 时诚实方被误罚损失 α_w·S* → v0.2 修复：摩擦加入 α_w·S*(ν)/n，明确市场可行条件 p − c_H ≥ min_ν F(ν)，否则触发「反向柠檬化」。
  • B4（R_verified 计量悖论与缓存套利）：按结果计费需每次核验（成本 κ_m），且二房东可缓存复用 h 次 → v0.2 修复：摩擦显式加上 κ_m，转售利润改为 k·p_resale − (k/h)·p_v − opex（仅 h≈1 退化为分销），并用履约回执防买方「看后拒采」。
  • B5（A 类私有状态与离线金丝雀结构冲突）：A 类价值在外部不可见的私有状态，L2 无法离线低成本抽检 → v0.2 修复：限定 L2 仅对可离线判定能力（D、部分 C）做金丝雀；A 类须事后实地核验（κ_A ≈ 履约成本 ∝ λ）并单列 Kill-Condition。
  • B6（Carry 与裁定合一导致拒赔/多罚利益冲突）：平台既做裁定又拿担保池盈余 carry 会诱导拒赔与滥罚 → v0.2 修复：裁定权剥离给独立核验方；罚没款只赔付受害租户或销毁（不进 carry 基数）；加高水位线与多期 clawback；ν 下限写入规则。
  • B7（漏质押解绑期约束）：作弊后若能在检测窗口结束前撤走质押则 IC 失效 → v0.2 修复：强制规定质押解绑期 ≥ 检测延迟 L + 申诉期，且后验信誉 V(T) 严禁用于下调 S 或 ν。
SPEC 已知边界（诚实声明 · 未建模或待实测项） Known Boundaries
  • 参数未实测：全部公式均为理论机制推导；L1/L3 的漂移率 λ、核验成本 κ、真实物理履约供给均未实测，三层商业可行性当前属于待检验假设。
  • 策略型故障率选择：作弊者可内生选择最优故障率 f（需对所有 f 满足 S ≥ sup_f nΔc(f) / (δ^L·D_α(f))，要求 Δc(f)/f 有界）。
  • 供给者–租户骗赔合谋：当单次赔付额 > 罚没质押 S 时，供给者与假租户自导「履约失败」骗取保险赔付有利可图。
  • 刷单抬升 n 与 V(T)：攻击者可通过自买自卖刷单（单次成本仅 τ·p）人为做大调用量 n 与清白历史 V(T)，故 V(T) 绝不可用于减免质押。
  • 供给者–验证者合谋：独立核验方若被收买会击穿分权假设，需多方异构 C-Gate 多数决与交叉审计。
  • C-Gate 自适应 Holdout 泄漏：多次自适应查询会通过 Blum–Hardt ladder 机制泄漏反例库信息，需严格执行查询限速、Thresholdout 加噪与反例动态轮换。
  • 基座模型共模故障：上游大模型版本更新或 API 故障会导致 C 类承保出现高度正相关的尾部集中赔付（不能仅用正态或独立 VaR 估算担保池 B）。
