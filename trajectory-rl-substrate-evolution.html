轨迹滚动与基质强化学习：当模型权重冻结，进化发生在环境侧
Trajectory Rollouts & Environment-Side Reinforcement Learning (Substrate RL)

当基座大模型参数 $\theta$ 被冻结或通过云端 API 租用时，智能体的持续进化并非权重反向传播（$\nabla_\theta$），而是环境侧强化学习（Substrate RL）——利用每一次会话轨迹滚动 $\tau$ 产生的验证反馈与局部搜索热耗散，在信赖域门控（rsi-gate）约束下，对外部认知基质 $E$（文件系统拓扑、规范化软链、@registry/bin-manifest $O(1)$ 查表、capability-registrar 语义路由与常驻宪章规则）执行拓扑梯度更新 $\nabla_E J(\pi_\theta, E)$。

1. 一分钟大白话导读：大脑是租来的，但「书房与路标」是你自己的

在今天的主流大模型工程中，有一个被普遍忽视的物理事实：你无法修改前沿大模型的权重 $\theta$。无论是调用云端闭源模型，还是在本地运行冻结权重的基座模型，每一次新会话启动时，模型本身的「脑细胞连接」都退回出厂设置。如果学习只能写进权重 $\theta$，那么智能体就永远困在「土拨鼠之日」——今天踩过的坑、花十步才翻出来的脚本，明天新会话一开，照样再盲搜十步。

核心洞察（Substrate RL 第一性原理）：
既然大脑权重 $\theta$ 是冻结的（租来的算力），学习就不能往脑子里写，而必须写进智能体身处的外部世界——即「外部认知基质（External Cognitive Substrate, $E$）」：它的目录拓扑、软链接（Symlinks）、~/bin/ 速查表、工具注册表和常驻规则。
🏃 每次会话 = 一次轨迹滚动 ($\tau$) 智能体从接手任务到最终通过验证器验收，走出的完整动作序列 $\tau = (s_0, a_0, r_0, \dots, s_T, a_T, R_{\text{verified}})$ 就是强化学习中的一次真实采样（Rollout）。
🔥 反复翻找 = 局部热耗散 ($T_d$) 当智能体为了找同一个文件（如 relay.py 或 codex-memory）连续执行 $\ge 3$ 次 find / ls / grep / read 时，这段盲目试探就是无用功（热力学耗散），也是环境侧最鲜明的预测误差信号。
⚡ 修路架桥 = 拓扑捷径压缩 系统捕获到高热耗散热点后，在安全门控（rsi-gate）批准下安装一条规范化软链或 @registry/bin-manifest 路由，把下一次滚动的 $O(k)$ 盲搜直接坍缩为 $O(1)$ 直达。

一句话总结：传统 RL 改变模型参数以适应固定环境；基质强化学习（Substrate RL）在固定模型参数下雕刻环境拓扑，让冻结的大脑在演化的世界中表现出指数级跃升的熟稔度。

2.2 核心数学形式化对象（Formal Mathematical Objects）

Object 1 · 轨迹滚动与环境侧策略目标 (Rollout & Substrate Objective)

设基座模型参数 $\theta \in \Theta_{\text{frozen}}$ 严格冻结（$\nabla_\theta \equiv 0$），外部认知基质 $E \in \mathcal{E}$（包含目录树、~/bin/ 软链、@registry/bin-manifest 与 capability-registrar 索引）为可学习结构参数。单次会话产生轨迹滚动：

$$\tau = (s_0, a_0, r_0, \dots, s_T, a_T, R_{\text{verified}}), \quad s_{t+1} \sim \mathcal{T}(\cdot \mid s_t, a_t; E), \quad a_t \sim \pi_\theta(\cdot \mid s_t; E)$$

系统最大化期望已验证回报 $J(\pi_\theta, E) = \mathbb{E}_{\tau \sim (\pi_\theta, E)}[R_{\text{verified}}(\tau)]$。对基质 $E$ 求环境侧策略梯度（Score-Function / Environment Gradient）：

$$\nabla_E J(\pi_\theta, E) \approx \mathbb{E}_{\tau} \left[ \sum_{t=0}^{T} \nabla_E \log \pi_\theta(a_t \mid s_t, E) \cdot \big(R_{\text{verified}}(\tau) - b\big) \right]$$

其中 $b$ 为滑动平均回报基线（Baseline）。关键物理分野：$\theta$ 完全冻结，$E$ 是唯一可更新的参数空间。

Object 2 · 三因子基质更新方程 (Three-Factor Substrate Update Rule)

针对离散工具与文件系统拓扑，连续梯度离散化为非反向传播三因子局部更新算子：

$$\Delta E_{\text{path}} \propto \underbrace{e_{\text{path}}(\tau)}_{\text{局部绕行资格迹}} \cdot \underbrace{g_{\text{coord}} \in \{0, 1\}}_{\text{rsi-gate 协调准入门}} \cdot \underbrace{\big(R_{\text{verified}}(\tau) - b\big)}_{\text{确定性验证标量反馈}}$$

其中资格迹 $e_{\text{path}}(\tau) = \sum_{t=0}^T \gamma^{T-t} \mathbb{I}[\text{action } a_t \text{ probes or traverses } \text{path}]$ 记录了当前滚动中实际走过的探索路径强度。

Object 3 · 路径与注册表项的 Beta 后验效用 (MemRL Beta Utility Extended to Paths)

将 MemRL 效用函数从记忆块扩展至每一条文件系统路径、软链与 capability-registrar 条目 $\text{path} \in E$，每个条目维护独立的 Beta-Bernoulli 共轭先验参数 $(\alpha_{\text{path}}, \beta_{\text{path}})$：

$$Q(\text{path}) = \frac{\alpha_{\text{path}}}{\alpha_{\text{path}} + \beta_{\text{path}}}, \quad \begin{cases} \alpha_{\text{path}} \leftarrow \alpha_{\text{path}} + 1 & \text{若调用该路径且导向 } R_{\text{verified}} = 1 \text{（有效命中）} \\ \beta_{\text{path}} \leftarrow \beta_{\text{path}} + 1 & \text{若发生 } \ge 3 \text{ 步探索绕行或查找未命中（Detour/Miss）} \end{cases}$$

当候选捷径的目标构件累积高频摩擦、且安装后的后验效用满足 $Q(\text{path}) \ge \tau_Q$ 并通过信赖域门控时，拓扑捷径被正式固化进基质 $E$。

Object 4 · 信赖域复杂度门控 (SkillProx / RRSI Trust-Region Gate)

为防止基质无界膨胀、语义漂移或破坏既有不变量，rsi-gate 实施严格的单步信赖域约束（Fail-Closed）：

$$\text{Admit}(E_{\text{new}} \leftarrow E_{\text{old}} + \Delta E) \iff D_{\text{sub}}(E_{\text{new}} \parallel E_{\text{old}}) \le \delta \;\land\; \text{Invariants}(E_{\text{new}}) = \text{PASS}$$

其中 $D_{\text{sub}}(E_{\text{new}} \parallel E_{\text{old}})$ 度量行为策略偏移与描述长度增量（KL / 最小描述长度复杂度步长）。一旦超出半径 $\delta$，修改立即被拒绝并回滚。

Object 5 · 热耗散信号与拓扑捷径退火 (Dissipation-Driven Shortcut Compression)

定义系统的轨迹绕行温度（Detour Temperature） $T_d$ 为落在连续探索绕行片段（$\ge 3$ 步连续 find/ls/grep/read）中的动作占总动作的比例：

$$T_d(E) = \frac{N_{\text{actions\_in\_detours}}(E)}{N_{\text{total\_actions}}(E)}, \qquad \Delta \mathbb{E}_{\tau}\big[|\text{detour}(v^*)|\big] : \underbrace{O(k)}_{\text{多跳探索探针}} \xrightarrow{\text{Install Canonical Shortcut } e^*=(s_0 \to v^*)} \underbrace{O(1)}_{\text{直接索引查表}}$$

每次在高频热点 $v^*$ 上安装规范化软链或 @registry/bin-manifest 条目，都相当于在图上跨过 $k$ 步中间试探节点直接连边，单调降低期望路径长度 $\mathbb{E}[|\text{detour}|]$ 并使系统温度 $T_d(E)$ 退火下降。

3. 三因子信用分配的环境侧映射（Three-Factor Credit Mapped to Substrate）

为什么不能直接让智能体「想到什么就改什么配置文件」？在非反向传播理论中，缺少门控与验证标量的双因子 Hebbian 学习（只要同时激活就强化）必然导致噪声自激与失控漂移。Substrate RL 必须严格集齐三个正交因子才能触发一次基质写入：

因子 I · 局部资格迹 ($e_{\text{path}}$)

物理含义：智能体在本次滚动中真实走过的探索路径与绕行热迹。
环境映射：当智能体为定位 relay.py 连续触发 find $\to$ grep $\to$ read 时，该路径上的摩擦计数器点亮资格迹 $e_{\text{path}} > 0$。没有真实踩坑的臆想优化，资格迹为 0，不予触发。

因子 II · 协调与信赖域门控 ($g_{\text{coord}}$)

物理含义：调制神经递质 / 谱隙与信赖域准入开关 $g_{\text{coord}} \in \{0, 1\}$。
环境映射：由顶层协调器与 rsi-gate 联合把关：检查修改步长 $D(E_{\text{new}} \parallel E_{\text{old}}) \le \delta$、红线不变量与零退化回归测试。任一不满足则 $g_{\text{coord}} = 0$（Fail-Closed）。

因子 III · 验证器标量反馈 ($R_{\text{verified}} - b$)

物理含义：带符号的全局多巴胺预测误差信号。
环境映射：严禁执行智能体自报完成！必须由独立确定性验证器（如 surface-verify、selftest.sh、契约校验）给出客观回执 $R_{\text{verified}}$。高于基线 $b$ 则强化固化（$\alpha+1$），否则记为耗散教训（$\beta+1$）。

5. 从精确科学计算到通用智能体工程：四条普适元规则

From Scientific Computing to General Agent Engineering: Four Universal Meta-Rules (BootLoops vs Substrate RL)

为什么一套在精密数学物理与高能自举计算（BootLoops）中锻造出的研究支架，能够无缝迁移到日常全栈软件与多智能体协同控制面？核心原因在于：当你剥离掉 BootLoops 的精确科学计算外壳（符号代数、百位任意精度球算术、解析延拓），底下暴露出的同一组四条结构不变量（Four Structural Invariants），同样统治着通用智能体工程。 这正是同一个「活体工作台（Living Harness）」在环境侧强化学习（Substrate RL）中的同构实现。

结构同构映射：剥离科学计算外壳 → 通用智能体控制面核心 (Science Shell Stripped → Universal Living Harness Core) Isomorphic Invariants

Rule 1 · 正交性公理

单通道自检永远无法发现与生成过程同源的盲区。唯有让「符号/逻辑通道」与「数值/视觉像素通道」彼此正交对撞，才能刺穿看似自洽的幻觉。

Rule 2 · 诚实边界公理

区分「已验证真值」与「未知区间」是智能体可信赖的底线。跨零球拒绝认证与 QUARANTINED_MISSING_AUTHENTIC_ASSET 本质上是同一条认识论停机坪。

Rule 3 · 时间因果不可逆公理

先射箭后画靶会让一切验证坍缩为恒真重言式。通过 claim-seal 在时间轴上冻结判准 SHA-256，从密码学上封死了奖励黑客的退路。

Rule 4 · 耗散结晶公理

7. 结语与可证伪反信号（Conclusion & Falsifiability Anti-Signals）

科学的理论必须声明什么观测结果能够推翻自己。如果「基质强化学习（Substrate RL）」仅仅沦为把更多文档塞进仓库的修辞包装，而不能在后续的只读轨迹审计中产生可测量的物理退火，则该机制应当被判伪并触发回滚。我们确立以下四条硬性可证伪反信号（Falsifiability Anti-Signals）：

反信号 1 · 基质膨胀但期望绕行长度不降（Substrate Bloat without Compression）
若安装规范化软链、@registry/bin-manifest 与 capability-registrar 路由后，后续 500 个会话中的全局绕行温度 $T_d$ 未从 8.89% 显著下降，或目标热点构件的 $\mathbb{E}[|\text{detour}|]$ 仍维持在 4.67 步附近，说明捷径未被策略分布 $\pi_\theta(\cdot \mid s_t, E)$ 有效感知，应立即移除无效索引。
反信号 2 · 路径效用 $Q(\text{path})$ 校准失真（Miscalibrated Beta Utility）
若高 $Q(\text{path}) = \alpha/(\alpha+\beta)$ 的路径在实际调用中并未带来更高的 $R_{\text{verified}}$ 通过率（即自报命中与独立验证回执脱钩），说明 $(\alpha,\beta)$ 更新混入了未验证的虚假正反馈，必须重绑确定性验证器。
反信号 3 · 信赖域过紧导致僵死，或过松导致漂移（Trust-Region Pathology）
若 $\delta$ 设得过小导致 100% 的高频热点压缩提案被拒（零学习率），或 $\delta$ 设得过大导致常驻规则发生语义冲突与不可审查的脚本覆写，则表明复杂度度量 $D(E_{\text{new}} \parallel E_{\text{old}})$ 失准。
反信号 4 · 别名歧义引发新的探测环路（Shortcut Aliasing Loops）
若新增的软链或注册表项与既有同名构件（如 relay 与 relay.py）产生新的命名冲突，反而诱发智能体执行额外的 which / stat / read 消歧探针，则净热耗散 $\Delta T_d > 0$，必须触发自动合并或剪枝。
